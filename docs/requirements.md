## 4. 架構

前端為主 + 輕量後端。圖片處理全在前端(Canvas),後端只做抓圖代理。

| 部分 | 技術 | 職責 |
|------|------|------|
| 前端 | React + Vite + TypeScript | UI、參數調整、Canvas 圖片處理、JSZip 打包 |
| 後端 | Node.js + Fastify + Playwright | 只做抓圖:爬頁面、SSRF 防護、代理下載 |
| 部署 | Docker Compose(nginx 前端 + node 後端) | 一鍵起 |

**為什麼處理放前端**:①使用者上傳的圖不經伺服器(隱私)②批量運算用使用者自己電腦(後端零負擔)③調透明度時 Canvas 直接重繪(即時預覽免費)。
**取捨**:若未來單批數百張或超大圖,瀏覽器記憶體吃緊,再把處理搬後端(sharp)。100 張內先不做。

## 5. 使用流程

```
輸入網址 → 後端抓圖 → 縮圖牆勾選
   ↓ (或直接上傳本地圖,跳過抓圖)
選處理:馬賽克 and/or 浮水印
   ↓
調參數 + 單張即時預覽
   ↓
批量套用(進度條)→ ZIP 打包下載
```

## 6. ⚠️ 公網部署的關鍵風險(部署前必解)

抓圖目標含成人與登入牆社群網站,加上公網開放,產生以下必須先解決的問題:

1. **SSRF**:抓圖代理能下載任意 URL,必須封鎖內網位址等(細節見 [01-image-scraping.md](features/01-image-scraping.md) 第 5 節)
2. **開放代理濫用**:公網開放會被當免費爬蟲,必加登入授權 + rate limit
3. **成人內容合規**:多數雲端商(AWS/GCP/Vercel)禁止託管成人內容服務,部署平台需自行確認
4. **著作權 / 肖像權**:批量抓取+加工+散布他人圖片可能侵權;含真實人物照片涉隱私

**強烈建議**:抓圖功能設為「僅本機 / 白名單使用者」,圖片處理功能才對公網開放。
